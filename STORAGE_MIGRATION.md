# Зберігання даних LadySite

Застосунок використовує стандартний модуль Python `sqlite3`. MySQL і PyMySQL для запуску більше не потрібні.

- `DATA/lady.db` — користувачі, хеші паролів, записи клієнтів, статистика відвідин і старий аудит.
- `DATA/pages.json` — робочі сторінки, послуги, меню послуг та спільні блоки. Зберігайте наявні ручні зміни.
- `DATA/default_pages.json` — початкові сторінки для нового встановлення. Не замінює наявний `pages.json`.
- `DATA/LadySite.config` — текстовий конфіг; `SQLITE_PATH=DATA/lady.db`. Відносний шлях рахується від каталогу застосунку.
- `logs/Lady_YYYY-MM-DD_log.csv` — поточний журнал. Старий аудит у SQLite доступний для перенесення в CSV.

## Перенесення, виконане локально 2026-10-27

Дані прочитано з MySQL у транзакції з узгодженим знімком без запису до джерела. Експорт і копії попередніх `LadySite.config` та `pages.json` збережено в `DATA/migration-backup-20261027-112445/`. Цей каталог містить приватні дані та не потрапляє в Git.

Звірено всі поля експортованих рядків: 2 користувачі, 136 відвідин, 4 записи старого аудиту, 9 розділів і 33 картки послуг; записів клієнтів на момент знімка було 0. Хеші паролів, ідентифікатори, дати, ролі й ознаки блокування збережені. Початкові таблиці послуг залишено в SQLite як архів; застосунок читає й редагує послуги виключно в JSON.

Послуги перетворено на 43 блоки та 9 пунктів меню в `DATA/pages.json`. Посилання на створені раніше сторінки, тексти, ціни, малюнки, порядок та приховані елементи збережені. У редакторі можна змінювати блоки, їхні якорі та пункти меню; порожнє меню теж зберігається.

## Повторне перенесення з JSON-експорту

Перед імпортом збережіть резервну копію робочих файлів. Команда нижче читає JSON-експорт таблиць, а не підключається до MySQL:

```powershell
python -m Utils.migrate_storage DATA/migration-backup-20261027-112445/mysql-export.json
```

Команда відмовиться замінювати наявний `lady.db` або наявну JSON-сторінку `/services`. Для перевірки іншого експорту використовуйте окрему копію застосунку та його DATA. Порожня SQLite автоматично отримує схему, але не стандартний акаунт із відомим паролем: для цього сайту потрібна перенесена база з наявними користувачами.

## Оновлення сервера

Локальні зміни ще не розгорнуті. Перенесення на сервер потребує актуального знімка на момент перемикання, щоб не втратити зміни після локального експорту. Перед перемиканням зупиніть запис до старої версії та збережіть її DATA і файли малюнків.

Розмістіть узгоджені `DATA/lady.db`, `DATA/pages.json`, конфіг із `SQLITE_PATH` та потрібні файли `static/service_images/`. Каталог DATA має бути доступним процесу застосунку для запису і не повинен роздаватися як статичний вебкаталог. Встановіть `requirements.txt` та запускайте нову версію після перенесення даних. Вихідну MySQL не видалено.

Для копіювання SQLite під час роботи використовуйте SQLite backup API: файл `lady.db` може мати активні супутні файли `-wal` і `-shm`. Альтернатива — копіювати базу після повної зупинки застосунку.
